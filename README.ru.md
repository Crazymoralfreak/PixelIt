# PixelIt

[English](README.md)

Набор инструментов для изображений под Windows и macOS: просмотрщик, недеструктивный редактор, пакетная обработка по рецептам, генераторы наборов и локальные модели ИИ. Всё работает на вашем компьютере. Одни и те же операции доступны в окне, из командной строки и ИИ-агентам через MCP.

Интерфейс доступен на немецком, английском, испанском, французском, японском, корейском, польском, португальском, русском, турецком и китайском (упрощённом) языках. Учётной записи в приложении нет. В сеть оно обращается только за тем, о чём вы попросили: проверка обновлений, загрузка моделей, запросы к серверам и сервисам, которые вы сами настроили.

## Скачать

Последняя версия лежит на странице [релизов](https://github.com/Crazymoralfreak/PixelIt/releases/latest):

- `PixelIt_<версия>_x64-setup.exe` — установщик. Ставит приложение текущему пользователю, права администратора не нужны.
- `PixelIt_<версия>_x64-portable.zip` — portable-версия. Распакуйте папку `PixelIt` в любое место и запустите `PixelIt.exe`. Файл `portable` рядом с программой означает, что все данные она хранит в папке `data` рядом с собой.

Тег также собирает образы диска macOS: `PixelIt_<версия>_MacOS_Silicon.dmg` для Apple Silicon и `PixelIt_<версия>_MacOS_Intel.dmg` для Intel. Образ подписан локально, без сертификата Apple, поэтому Gatekeeper спросит перед первым открытием. Меню Проводника, снимок экрана, HEIC и локальные модели ONNX остаются в Windows. Сама себя обновляет установленная копия для Windows.

Файлы не подписаны сертификатом подписи кода, поэтому Windows SmartScreen при первом запуске покажет предупреждение.

## Что умеет

- **Просмотр.** Папки с миниатюрами, сортировкой и фильтром; размер, формат, глубина цвета и метаданные каждого изображения. Файлы открываются перетаскиванием, через диалог, из буфера обмена (Ctrl+V), из проводника и аргументами запуска.
- **Из сети.** Изображения по ссылке — пин Pinterest, любая веб-страница или прямой адрес изображения — и поиск в каталогах Openverse и Wikimedia Commons со свободными лицензиями. Учётная запись и ключи не нужны. Скачанное открывается в редакторе или уходит в пакет; источник, автор и лицензия сохраняются в журнале. Ссылку можно вставить через Ctrl+V из любого места программы.
- **Форматы.** Читает JPEG, PNG, WebP, AVIF, JPEG XL, HEIC, TIFF, GIF, BMP, ICO, RAW фотокамер, SVG, PDF и PSD. Пишет JPEG, PNG, WebP, AVIF, JPEG XL, TIFF, GIF, BMP и ICO. 16 бит на канал сохраняются там, где формат их поддерживает.
- **Редактор.** Стек шагов, который не меняет исходный файл: размер, кадрирование, поворот, отражение, коррекция, фильтры, водяные знаки, аннотации. Сравнение «до и после», отмена и повтор, оценка размера и сравнение форматов перед сохранением.
- **Пакет.** Очередь файлов и папок с параллельной обработкой, паузой, отменой и оставшимся временем. Целевой размер файла, подбор качества по визуальному сходству, автоматический выбор самого компактного формата.
- **Рецепты и наблюдаемые папки.** Рецепт — сохранённый набор шагов и настроек вывода; его можно экспортировать файлом. Наблюдаемая папка обрабатывает рецептом каждое новое изображение.
- **Журнал.** Каждый запуск записывается и отменяется: новые файлы уходят в корзину, заменённые возвращаются.
- **Инструменты.** Наборы иконок, размеры для соцсетей, адаптивные наборы для сайта с готовым HTML, коллаж, PDF из изображений, анимация GIF, WebP и APNG, поиск одинаковых и похожих изображений, снимок экрана по горячей клавише.
- **Windows.** Значок в области уведомлений, автозапуск, ассоциации файлов, пункт «Открыть в PixelIt» в контекстном меню проводника, автоматические обновления.

## Модели и ИИ

Вместе с приложением ничего из этого не устанавливается. Модели и компоненты скачиваются на странице «Модели и ИИ» по вашему запросу, каждая проверяется по контрольной сумме.

- **Локальные модели** (ONNX Runtime с DirectML в Windows и Core ML на Apple Silicon, на видеокарте или процессоре): удаление фона, увеличение, удаление объектов, восстановление лиц. Они работают в отдельном процессе `pixelit-worker`, поэтому сбой внутри модели или видеодрайвера не роняет приложение.
- **Генерация изображений** через сервер ComfyUI или Forge / AUTOMATIC1111, встроенный stable-diffusion.cpp с вашим файлом модели либо внешний сервис с OpenAI-совместимым API и вашим ключом. В студии выбираются генератор и модель, включаются стили, создаются от одного до четырёх изображений, изображение можно изменить (целиком, по закрашенной области или за его краями), а всё сделанное остаётся в истории.
- **Понимание изображений** через модель с OpenAI-совместимым API (Ollama, LM Studio или внешний сервис): описания, alt-текст, ключевые слова, имена файлов, распознавание текста. Ответ можно записать в метаданные файла.
- **Ассистент.** Чат, который вызывает инструменты PixelIt и подключённых вами внешних MCP-серверов.

Правила приватности:

- Внешние сервисы выключены, пока вы их не включите, и перед отправкой изображения или запроса PixelIt спрашивает подтверждение. Сервер на этом компьютере (адрес обратной петли) считается локальным.
- Ключи хранятся в диспетчере учётных данных Windows, а не в файлах настроек.
- Ассистент и внешние агенты работают только в разрешённых вами папках. Перезапись, удаление, загрузка из сети (модели, компоненты, изображения) и внешние сервисы — отдельные разрешения, по умолчанию все выключены.
- Страница «Из сети» обращается к сети только по вашему действию: по вставленной ссылке, в выбранный каталог поиска и по адресам найденных изображений. Текст запроса уходит только в выбранный каталог. Агентам адреса этого компьютера и локальной сети закрыты.

## Обновления

Установленная версия при запуске спрашивает у GitHub, вышла ли новая. О найденной версии PixelIt сообщает и спрашивает, устанавливать ли её: «Обновить», «Позже» или «Пропустить эту версию». Без согласия ничего не скачивается. После согласия установщик скачивается, его подпись проверяется, и он запускается, когда не выполняется ни одна задача; после установки PixelIt запускается снова. Рецепты и настройки сохраняются.

- Проверка выключается в настройках. Без неё PixelIt сам к GitHub не обращается.
- Канал «бета» в настройках предлагает и предварительные версии.
- Portable-версия сама не обновляется: она только сообщает, что вышла новая версия.
- После обновления окно «Что нового» показывает изменения новой версии из `CHANGELOG.ru.md`; вся история есть на странице «О программе».

## Командная строка

`PixelIt.exe` — это и консольная программа: если первым аргументом стоит команда, она выполняется без открытия окна.

```
PixelIt convert photos --format webp --quality 80 --max-width 1920 --output out
PixelIt run web photos --recursive
PixelIt recipes
PixelIt info photo.jpg --json
PixelIt compare photo.png --formats jpeg,webp,avif,jxl
PixelIt duplicates photos --recursive --tolerance 6
PixelIt help
```

- `convert` — конвертировать, сжать или уменьшить; `run` — обработать сохранённым рецептом (его идентификатор, имя или экспортированный файл).
- Новые файлы пишутся в папку `PixelIt` рядом с каждым исходным, если `--output` не называет другую папку. Существующие файлы заменяются только с `--overwrite`; заменённые уходят в корзину.
- `--json` печатает результат для скриптов. Код возврата 0 при успехе, 1 — если хотя бы один файл не обработан, 2 — при неверной командной строке.
- `PixelIt.exe` — оконная программа, поэтому интерактивные `cmd` и PowerShell её не ждут и показывают приглашение раньше, чем закончится вывод. В скрипте дожидайтесь её явно: `start /wait PixelIt.exe ...` в `cmd` или передача вывода дальше (`PixelIt.exe info a.jpg | Out-String`) в PowerShell.

## MCP-сервер

`PixelIt.exe mcp` — MCP-сервер на стандартных вводе и выводе. Агент (Cursor, Claude Desktop и другие MCP-клиенты) получает те же инструменты, что и встроенный ассистент: `list_images`, `image_info`, `list_recipes`, `run_recipe`, `convert`, `run_pipeline`, `compare_formats`, `find_duplicates`, `undo`, `ai_status`, `remove_background`, `upscale`, `restore_faces`, `generate_image`, `describe_image`, `install_component`, `find_web_images`, `download_web_image`.

На странице «Модели и ИИ», вкладка «MCP», показан готовый текст для настроек клиента. Его форма:

```json
"mcpServers": {
  "pixelit": {
    "command": "путь к PixelIt.exe",
    "args": ["mcp"]
  }
}
```

Там же задаётся, что агентам разрешено: разрешённые папки и отдельные разрешения на перезапись, удаление, загрузку из сети и внешние сервисы. По умолчанию сервер пишет только новые файлы и ничего не скачивает.

PixelIt — ещё и MCP-клиент: на той же вкладке подключаются внешние MCP-серверы (программа через стандартные потоки или адрес с транспортом Streamable HTTP), с разрешением для каждого инструмента: разрешить, спрашивать или запретить.

## Требования

- Windows 10 версии 1809 или новее, либо Windows 11, x64. macOS 11 или новее, Apple Silicon или Intel.
- Среда выполнения WebView2. В Windows 11 она есть всегда. Установщик на машине без WebView2 скачивает её сам; portable-версия без неё не запустится.
- Файлы HEIC читаются кодеками Windows: нужны «Расширения для изображений HEIF» и «Расширения для видео HEVC» из Microsoft Store.
- Файлы PDF читает компонент PDFium, он скачивается на странице «Модели и ИИ».
- Видеокарта используется через DirectML, если она есть; без неё модели работают на процессоре, медленнее.

## Данные

Рецепты, настройки, журнал, чаты, скачанные модели и кэш миниатюр лежат в `%AppData%\PixelIt`. Portable-версия хранит их в папке `data` рядом с `PixelIt.exe`. Изображения из сети сохраняются там же, в папке `downloads`, пока в настройках не выбрана другая. Одновременно работает только один экземпляр; второй запуск передаёт свои файлы первому.

При удалении программы папка остаётся. Её стирает отдельная галочка в окне удаления, по умолчанию она выключена.

## Сборка

Нужны:

- Node.js 20.19 или новее (либо 22.12 и новее);
- Rust 1.98 или новее с набором инструментов `x86_64-pc-windows-msvc`;
- Microsoft C++ Build Tools и NASM (в кодировщиках JPEG, WebP и AV1 есть части на C и ассемблере).

```
npm install
npm run tauri build
```

После сборки:

- установщик: `target\release\bundle\nsis\PixelIt_<версия>_x64-setup.exe`;
- программа: `target\release\PixelIt.exe`. Локальным моделям рядом с ней нужен ещё `pixelit-worker.exe`: `cargo build --release -p pixelit-worker`.

Portable-копия — это папка с `PixelIt.exe`, `pixelit-worker.exe` и пустым файлом с именем `portable`. Папку `portable` в корне репозитория Git пропускает, поэтому копию для пробы можно держать там.

Режим разработки:

```
npm run tauri dev
```

## Выпуск версии

1. Поставить новый номер версии в трёх файлах: `package.json`, `src-tauri/tauri.conf.json` и корневом `Cargo.toml` (`[workspace.package]`), и добавить раздел версии в `CHANGELOG.md` и `CHANGELOG.ru.md`.
2. Закоммитить изменения и поставить на этот коммит тег `v<версия>`, например `v1.1.0`.
3. Отправить тег на GitHub.

По тегу запускается `.github/workflows/release.yml`: проверяет, что номер в теге совпадает с номером в трёх файлах, прогоняет тесты, собирает и подписывает установщик, собирает portable-архив и прикрепляет их к релизу этого тега. Тот же тег собирает образы диска macOS (с рабочим процессом моделей внутри приложения) и затем пишет `latest.json` для Windows и обоих вариантов Mac. Описанием релиза становится раздел версии из `CHANGELOG.md`.

`latest.json` — описание обновления: номер версии, ссылка на пакет каждой системы и его подпись. Установленные копии читают его по адресу `releases/latest/download/latest.json`, поэтому обновление увидят только у релиза, который GitHub считает последним: не у черновика и не у предварительного. Образ диска macOS подписан локально (ad-hoc); Gatekeeper спрашивает перед первым открытием, пока не настроены секреты нотаризации Apple.

Тег с суффиксом, например `v1.1.0-beta.1`, создаёт предварительный релиз. Копии на канале «бета» читают манифест постоянного релиза `beta-channel`, который обновляется при каждом выпуске.

### Ключ подписи обновлений

Приложение ставит только то обновление, чья подпись сходится с открытым ключом из `src-tauri/tauri.conf.json` (`plugins.updater.pubkey`). Закрытого ключа и пароля к нему в репозитории нет. Их место — секреты GitHub Actions `TAURI_SIGNING_PRIVATE_KEY` и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`.

Если закрытый ключ потерян, уже установленные копии обновить нельзя: придётся выпустить версию с новым открытым ключом и ставить её вручную.

Подпись включается файлом `src-tauri/tauri.release.conf.json`, который подключает только сборка релиза. Обычной локальной сборке ключ не нужен; её установщик не подписан.

## Проверки

```
npm run typecheck
npm run i18n:check
npm run licenses:check
cargo fmt --all --check
cargo clippy --workspace --all-targets
cargo test --workspace
```

`.github/workflows/ci.yml` запускает их на каждый push и pull request, вместе с `cargo deny` (лицензии и источники зависимостей, `deny.toml`) и модульными тестами ядра под Miri.

- **Свойства.** `crates/pixelit-core/tests/properties.rs` проверяет изменение размера и геометрию на сгенерированных значениях.
- **Повреждённые файлы.** `crates/pixelit-codecs/tests/damaged.rs` обрезает и портит файлы каждого формата; чтение должно закончиться изображением или ошибкой, но не падением. Декодер AV1 на повреждённом файле может остановить весь процесс, поэтому PixelIt декодирует AVIF в короткоживущей копии самого себя (`PixelIt.exe --decode-avif`) и сообщает о таком файле как о нечитаемом.
- **Эталонные образцы.** `crates/pixelit-codecs/tests/golden.rs` сравнивает результат каждой операции с картинкой из `crates/pixelit-codecs/tests/golden`. После намеренного изменения операции картинки записываются заново: workflow «Golden samples», который запускается вручную, или запуском теста с `PIXELIT_BLESS=1`.
- **Фаззинг.** В `fuzz/` лежат цели `cargo fuzz` для декодеров, кода метаданных и чтения рецептов; `fuzz.yml` запускает их раз в неделю.
- **Бенчмарки.** `bench.yml` запускает бенчмарки criterion раз в неделю и вручную.

`src/licenses.json`, список на странице «О программе», собирается из `Cargo.lock` и `package.json` командой `npm run licenses`. Иконки в `src-tauri/icons` рисует `npm run icons`.

## Устройство

- `crates/pixelit-core` — буферы пикселей, операции и модель рецепта (`Pipeline`).
- `crates/pixelit-codecs` — чтение и запись форматов, управление цветом, метаданные.
- `crates/pixelit-engine` — исполнение рецептов, пакет, очередь задач, хранение, наблюдаемые папки, генераторы, журнал.
- `crates/pixelit-ai` — компоненты и модели, клиент процесса моделей, провайдеры генерации, модели, понимающие изображения.
- `crates/pixelit-worker` — отдельный процесс, в котором работает ONNX Runtime.
- `crates/pixelit-tools` — единый реестр инструментов для ассистента и MCP-сервера.
- `crates/pixelit-mcp` — MCP-сервер и клиент внешних MCP-серверов.
- `crates/pixelit-cli` — командная строка.
- `src-tauri` — приложение: окно, трей, горячие клавиши, обновления, интеграция с Windows, команды для интерфейса.
- `src` — интерфейс на React и TypeScript: страницы в `pages`, словари в `i18n`, типы — зеркало модели Rust — в `types`.
